What stood out

Where the data comes from

The headset never talks to this laptop directly. It has wifi in it, and it sends what it reads to Neurosity's servers. Anything that wants that data — their console, their phone app, this project — signs in to that cloud and asks for it.

Everything to the right of the CSV never touches the internet. That is deliberate: it means this runs on sample data, runs offline, and runs for someone who has no Neurosity account at all.

Try it in thirty seconds · no headset needed

  1. Get the code running. You need Node installed. Nothing else — no dependencies, no account, no API key.
    cd crown-debrief
  2. Make some sample data. Writes a synthetic fortnight into data/. It is labelled as synthetic everywhere it appears, so it can never be mistaken for a real recording.
    npm run sample
  3. Start it. Then open the address it prints.
    npm start

Recording a real session

  1. Wake the headset. Hold the power button until it lights up, then check it appears as online at console.neurosity.co. A Crown that has been in a drawer will usually need to rejoin wifi.
  2. Put your credentials in a file called .env. Copy the example and fill in your Neurosity email and password. That file is excluded from version control and never leaves the machine.
    cp .env.example .env
  3. Install the one real dependency. The Neurosity SDK is only needed for live recording; everything else runs without it.
    npm install
  4. Fit it properly, then record. Electrodes need to reach scalp, not sit on hair. Work normally for an hour or more — short sessions do not give patterns room to appear.
    npm run log:live
  5. Stop with Ctrl+C. The new CSV lands in data/ and shows up in the session list on its own. Nothing else needs changing.
Check the data is real before trusting it. Close your eyes for thirty seconds, then open them for thirty. Alpha should rise while they are shut — it has been the most reproducible finding in EEG since the 1920s, which makes it the one thing you can test that has a known right answer. If it does not move, the problem is the fit or the connection, and you have found out in a minute instead of after a day of confusing results.

Reading a session

  1. Start with the one number. Deep work is the time spent meaningfully above your own normal. It is minutes rather than a score on purpose — minutes cannot be misread as a percentage, and counting them does not grade anyone's brain.
  2. Read position, not size, on the gauges. The shaded band is your usual range. Inside it is a normal day. There is no target to hit.
  3. Look at the ribbon for the shape of the day. Colour carries meaning and nothing else uses those colours. Hatching means the signal was too poor to read, and a faint gap means recording stopped — neither is a brain state, and neither is ever drawn as one.
  4. Say what you were doing. The headset records when something changed and is permanently silent on why. A one-line note against a dip is the only thing that can supply it, and after a few weeks those notes turn the chart into an explanation.
  5. Ask the guide anything. On the Today screen. Every answer says where it came from, and when it does not know it says so rather than guessing.

When something goes wrong

"Port is already in use"Another dev server is on that port. The message tells you how to find and stop it, or use PORT=5274 npm start.
Coverage is lowThe electrodes were not reaching scalp. Below 75% treat the rest as provisional; below 50% refit and record again.
"Learning what's normal for you"Working as intended. Comparisons need ten sessions. Until then the app says so rather than inventing one.
Live mode will not connectCheck the Crown is online in the Neurosity console first, then that .env has the right email, password and device ID.
Numbers look wrongRun npm test. Seventy-five checks cover the parsing, the quality gate and the statistics. If those pass, suspect the headset fit before the code.

What this is not

Worth saying plainly, because every design choice here makes the data feel more authoritative than it is.

  • Not a medical device. Focus and calm are probability scores from a consumer headset. Nothing here is a health assessment and the app makes no clinical claims.
  • Not a measurement. Neurosity derives focus from gamma and calm from alpha using models trained in advance. A reading of 0.42 means a classifier put the probability at 0.42 — and their own documentation notes that anything above 0.3 is already significant.
  • Not a step toward moving a robotic arm, yet. Focus and calm say how you are. Imagining a movement is a different signal saying what you want, and the second cannot be derived from the first. What this does build is the recording discipline that work would depend on.
  • Not sending your data anywhere. Recordings and notes are files on this machine. The published version reads a dropped file inside the visitor's own browser and uploads nothing.

Everything below is for building and debugging, not for reading a session. Watching a live focus score while you work reliably lowers it.
